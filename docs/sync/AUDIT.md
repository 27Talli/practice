## Business behavior and write boundaries

| Feature | Audited implementation | Required integration point |
| --- | --- | --- |
| Product create/edit/association | `RoomRepositories.kt`; registry identity shared, prices/stock shop-specific; initial stock movement created | Enqueue complete catalog/association/opening-stock operation in the same `withWriteTransaction` |
| Barcode edits | Manufacturer alias replacement is a real delete; internal SKU/cost aliases protected | Durable barcode tombstone plus new alias event; do not resurrect deleted aliases on pull |
| Cost labels | `RoomBarcodeLabelRepository`; shop key initialization can write during a settings read; immutable snapshot/random alias | Queue settings creation/change and label+alias creation atomically, including implicit initialization |
| Sale/payment | `RoomSalesRepository`; validates current price and local stock; snapshots and stock/audit/sequence commit together; request idempotency | Add global identities and complete sale outbox bundle before transaction commit; receipt immediately available |
| Discounts | Fixed line/order discounts; checked totals; original order-discount allocation retained for refunds | Send snapshots and allocations; never recompute historical revenue from current prices |
| Returns | `RoomFinanceRepositories.kt`; original-item remaining quantity validation, exact partial refund math, restock only saleable units | Server locks original sale items, recomputes remaining rights, handles offline conflicts explicitly |
| Exchanges | No atomic exchange feature/table currently exists | Preserve existing return+sale workflows; future linked exchange needs an explicit operation contract/test |
| Stock adjustments | Nonzero signed delta + required reason; update rejects negative stock | Send deltas with unique movement IDs, not resulting quantity |
| Purchases/transfers | No dedicated purchasing or transfer workflow currently exists | Do not claim they are already implemented; future operation types must have balanced, transactional movement contracts |
| Expenses | Idempotent create, audited void | Queue creation and separate void command; enforce role and revision remotely/local grant |
| Reports | Derived from local sale/refund/expense facts in a Room snapshot; PKT dates; inventory value shown separately | Download underlying facts and refresh Flow; do not synchronize report totals as independently editable data |
| Receipts | Saved snapshots → customer-safe document → preview/PDF/Android/ESC/POS; QR is printed receipt number | Keep identities/numbers immutable; support old and device-qualified receipt lookup; never upload staff cost into customer output |
| Staff price/profit | Read-only hidden dialog; cost/sale profit absent from receipts; secure window | Add actual role permissions where needed; a hidden icon is not authorization |
| Layout/selection | Device preferences and selected shop | Keep local; continue no-code customization |

`WorkspaceWriteGate` serializes mutations and prevents writes queued before restore from targeting a replaced dataset. Downloads/bootstrap/import/restore must respect it. Checkout's SavedStateHandle contains local IDs and pending request state; preserving those local keys avoids invalidating unpaid carts during ordinary migration.

## Critical findings

1. **IDs collide between devices.** Existing autoincrement IDs, per-shop SKU counters and receipt/return counters cannot be copied directly into a shared database. Add UUID mappings and device-qualified future numbers; keep old IDs/numbers/barcodes intact.
2. **No durable outbox exists.** Audit rows are not a replayable multi-table operation queue. Observing timestamps after a write is not atomic and can miss a process-kill boundary.
3. **Stock history assumes one writer.** Backup validation folds movements by local `id` and requires each historical `quantityAfter` to match. That does not describe concurrent devices. Preserve origin snapshots; add a canonical signed-delta projection and revise backup validation before importing remote movements.
4. **Oversell cannot fit the current stock cache alone.** `updateInventoryQty` rejects negative values, and backup validation rejects negative history. Store the signed consolidated balance/deficit separately, expose an explicit discrepancy, and derive sellable stock without erasing debt. Preserve all genuine sales.
5. **Report invalidation needs complete dependencies.** `observeFinanceChanges` tracks sales/returns/expenses/inventory/shop-products but not `products`, although current-stock valuation filters `products.isActive`. A future remote catalog-only activation change needs that dependency covered. Same-count updates to tracked tables can still emit through Room; test actual Flows rather than assuming every change must alter a count.
6. **Restore is incompatible with naive syncing.** Current backup format 1 explicitly supports database versions 5/6, lists 19 tables, replaces business rows on confirmed restore, and retains high counters/PIN/layout. New identities/outbox/checkpoints need an explicitly versioned portable backup/recovery design. Never clone live device credentials/checkpoints or replay old financial operations as new ones.
7. **Returns have a distributed-system limit.** Two completely disconnected devices can both refund the same last unit. Server checks can prevent duplicate canonical refunds, but cannot undo cash already handed out. Choose reserved offline refund rights/online cross-device authorization, or preserve provisional offline payouts as reconciliation exceptions. This choice must be visible, not hidden in last-write-wins.
8. **Local PIN is not cloud authorization.** No users/roles/shop access rules or device session binding exist. Add them to local command boundaries and server RPC/RLS, with safe offline access for enrolled devices.
9. **Device revocation has an offline limit.** A phone cannot learn of revocation with no communication. Client timestamps cannot prove an upload preceded revocation. Reject/quarantine new submissions after detected revocation and provide an owner recovery/review path; never silently erase pending local financial records.
10. **Version changes need coordinated validators.** Receipt lookup currently accepts only `OP-S-000001`/`FF-S-000001` style references. Barcode length is bounded; label aliases are max 80 characters. New device-qualified codes must satisfy scanning, label rendering, backups, receipt QR/lookup and retry tests together.
11. **Hardware/UI configuration is mixed with shared data.** Printer keys/USB choices, local security, layout and selected shop must not be copied as another phone's settings.
12. **Release signing remains a deployment gate.** Current debug release differs in signing key from older debug builds. Use the original retained key for in-place updates; do not uninstall a business installation to bypass signature checks. See `../SAFE_UPGRADES.md`.

## Backup verification boundary

No Android phone is attached to this workspace (`adb devices -l` was empty). No phone database has been exported or claimed verified. The user currently has test data only. Host rescue fixtures for schemas 3–6 were encrypted/decrypted and verified, including wrong-password rejection and existing-file protection. Existing native tests exercise encrypted export, inspect/stage, replacement, recovery and reopening; a fresh baseline CI run is used to record their execution before any future schema change.

Before a device migration, export its current encrypted backup, save an independent copy, inspect with the correct passphrase, restore on an isolated matching-variant test installation, compare both shops' counts/totals/stock/receipts and verify the recovery file. Keep the old installation and original signing key. Do not run a migration merely because a filename exists or a ciphertext hash matches. See `BACKUP_AND_TEST_PLAN.md`.
